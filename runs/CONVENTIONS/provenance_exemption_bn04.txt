# Provenance exemption manifest -- BN-04 (governor waiver, 2026-11-23)
#
# WHAT THIS IS
#   A closed, digest-locked list of twelve products that predate the tag regime and cannot
#   acquire a tag without being edited (s9.1 forbids editing archived products). Rule P9 of
#   docs/conventions/provenance_tags_v1.md classifies them EXEMPT-LEGACY: non-blocking, but
#   never OK.
#
# WHY A SECOND LIST AND NOT THE BASELINE
#   provenance_baseline.txt was frozen on 2026-11-22 as the inventory at adoption. These
#   twelve were written by the same production lines (SC, R1B p1-p4) that the convention was
#   adopted around, and the baseline snapshot simply does not contain them. Appending them to
#   a frozen manifest would silently extend a document whose own header says "append
#   deliberately; do not regenerate" -- i.e. it would use the grandfathering mechanism to
#   grandfather something new. A separate list that says "exemption" in its own name is
#   honest; a longer baseline would not have been.
#
# WHY NOT SIMPLY ADD A TAG
#   A tag written today would assert a provenance judgement made AFTER the numbers, which is
#   the retro-declaration problem of docs/specs/theta_camera_v1.md s0 one level down: a tag
#   claims "I classified this", and it cannot be dated. A digest claims only "this file is
#   what it was". The weaker claim is the true one.
#
# THE CLOSURE RULE (this is what makes P9 an exemption and not a hole)
#   The set is CLOSED. This file's own digest is in provenance_exemption_bn04.txt.sha256, and
#   the linter verifies it before honouring any line below. Editing this manifest -- to add a
#   thirteenth file, to change a digest -- invalidates the sidecar, voids the whole exemption,
#   and returns all twelve to MISSING. An exemption that can be extended is not an exemption;
#   it is a place to put things.
#
# FORMAT
#   <sha256>  <repository-relative path>       (two spaces, sha256sum -c compatible)
#
# SCOPE: these twelve only. Not their directories, not their kinds.
